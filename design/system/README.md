# Kindle Home — design system (案 B の洗練版)

Kindle Paperwhite 2（設計座標 1072 × 1448、実機 758 × 1024 / 212 dpi、16 階調）をスマホ風のホーム画面にする
デザイン一式。`design/mockups/` の案 B（エディトリアル / 新聞風）を出発点に、
C プログラム（stb_truetype + 矩形・線・円・PNG アイコン）で再現できる範囲へ
振り切ったもの。

## 成果物

| パス | 内容 |
|---|---|
| `screens/home.png` | 通常のホーム（お気に入り 3 件） |
| `screens/home-many.png` | お気に入り 9 件（6 件 / ページ、1 / 2） |
| `screens/home-empty.png` | お気に入り 0 件 |
| `screens/settings.png` | 設定（Wi-Fi ON、明るさ、新聞更新、再起動、標準画面、バージョン、戻る） |
| `screens/settings-wifi-off.png` | 設定（Wi-Fi OFF。レイアウトは ON と同一） |
| `screens/launching.png` | アプリ起動中 |
| `screens/sleep.png` | スリープ（スクリーンセーバー） |
| `src/*.html`, `src/base.css` | 各画面の絶対配置 HTML/CSS |

## 生成

```sh
bash design/system/render.sh
```

ヘッドレス Chrome で `src/*.html` を 1072 × 1448 / device scale 1 で撮影し、
Pillow で L モード + 16 階調（0, 17, …, 255）に量子化して `screens/` に上書きする。
アイコンは SVG を 1 枚のシートに描画して表示サイズで切り出し、同じ量子化をする
（画面 HTML は完成した PNG を 1:1 で貼るため、アイコンを先に生成する）。
Chrome は `CHROME=`、Python は `PYTHON=` で差し替え可能。`.venv` の Pillow を使う。

## 案 B から変えたこと / 残したこと

### 残したもの

- 大きなセリフ体の時計、3 px の罫線、字間の広い小見出し、マストヘッド、番号付きの
  お気に入りというエディトリアルな骨格。
- 白 + 黒 + グレー 2 段のみ。影・ぼかし・グラデーション・半透明は不使用。
- 8 px グリッドと 64 px マージン（案 B の 64 px を維持）。

### マストヘッドの意味

`NO. 043` は意味のない通し番号だったので、**通算日**に変えた。
`NO. 296 / 365` は 2026-10-23 が 296 日目であることを示す。0 埋め 3 桁
（1 月 1 日 = `NO. 001`）で、閏年は `/ 366`。日付が変わるときだけ全画面更新すれば
よく、毎分の部分リフレッシュとは独立している。

### 時計とステータスバー

- 時計は案 B の 276 px を **264 px** に整理し、字間 -8 px。画面の主役のまま。
  下半分のセクション間隔を確保するため、時計ブロックだけを少し圧縮した。
- 案 B はステータスバーにも小さな時刻があった。毎分更新する領域が 2 つに増えるので
  **ステータスバーの時刻を廃止**し、左は `WIFI / <SSID>` にした。SSID は日本語も
  可（796 px を超えたら `…`）。時計は `(48,192,976,336)` の 1 矩形だけを
  部分リフレッシュすればよい（SPEC §5）。
- 日付は `10月23日 金曜日`。曜日だけ gray-1。

### アプリアイコン

案 B の 4 つは線の太さと視覚サイズが揃っておらず、漫画が吹き出しで弱かった。
48 viewBox / stroke 3（96 px 表示で 6 px）に統一して描き直した。

- 新聞: 紙面・背・マストヘッド・黒ベタ写真・記事線。写真のベタで小サイズでも新聞と分かる。
- 漫画: **コマ割り**（4 コマ）に変更。吹き出しは使わない。ページ枠とコマ線だけで
  「漫画のページ」を表す。
- ブラウザ: 円 + 経線 + 緯線 3 本（案 B のグローブを継承）。
- 設定: ギアではなく **スライダー 3 本 + ノブ**。線幅を他と揃えやすく、設定と即座に分かる。

4 つとも 48 viewBox の同じ stroke 3、表示 96 × 96、円枠 160 × 160（4 px）。
視覚的な外接サイズは 28–34 units に揃えている。

### お気に入り: タイルとリストを両方試した

- **タイル案（採用）**: `screens/home.png`。3 列 × 2 行、288 × 184。96 × 96 の
  イニシャル枠（**5 px 枠 / 44 px イニシャル**）+ セリフ体の名前 + 通し番号 + 上罫線。
  1 ページ 6 件。
- **リスト案（不採用）**: `explorations/home-list.png`。案 B の索引を残し、80 × 80 の
  枠 + 番号 + 40 px の名前を 128 px 行で並べる。1 ページ 3 件。

タイル案を採った理由:

1. ユーザーの「スマホのホーム画面のアプリアイコン的」という要望に直結する。
   96 px の枠がアプリアイコンの位置に来て、名前がその下に付く。枠は 5 px に太くし、
   160 px のアプリ円と視覚的な重さを揃えた。
2. 6 件 / ページ vs 3 件 / ページ。9 件でも 2 ページで済み、ページ送りの回数が少ない。
3. タップ領域が 288 × 184 と大きく、E-ink でも押しやすい。
4. エディトリアルさは、上罫線・通し番号・セリフ体の名前・余白で担保できる。
   リスト案は美しいが、3 件ずつで頁が進むため「ホーム画面」より「索引」に見える。

名前が 256 px を超える場合は `…` で省略する（例: `はてなブック…`）。イニシャルは
Latin 2 語なら 2 文字、1 語なら 1 文字、日本語なら先頭 1 文字。C で枠と文字を描く。

### 追加行と空状態

- 0–3 件のときは第 2 行が空くので、944 × 184 の「ブラウザでお気に入りを追加」行を置く。
  タップでブラウザを開く。4–6 件では第 2 行が埋まるので出さない。追加行の下には
  罫線を引かず、フッター上罫線（y 1328）だけを残す（二重線を避ける）。
- 0 件は「まだ、ありません。」+ 案内文 + ＋枠 + 追加行。案内文は
  「ブラウザでお気に入りに追加すると、ここに並びます。」
- 7 件以上は 6 件 / ページ。フッターに `1 / 2` と前後シェブロン（120 × 120 タップ）。

### 設定・起動・スリープ

- 設定も同じマストヘッド・セクション見出し・3 px 罫線・8 px グリッド。項目名は
  ホームのアプリ名と同じ **SerifB**、値・状態は SansM。各行は「下に 3 px 罫線」だけの
  規則に統一し、行高は 128 / 136 / 200 / 64 px。Wi-Fi トグル、16 段階の明るさバー
  （－ / ＋）、新聞更新（200 × 120 ボタン）、再起動（›）、Kindle 標準画面（›）、
  バージョンを 1 画面に収めた。戻る矢印は文字の光学中心に合わせる。
- Wi-Fi OFF は `settings-wifi-off.png`。白地・3 px 枠・黒ノブ左のトグル、`オフ`、
  SSID gray-1、ステータス `WIFI / OFF`。
- 起動はアプリの円アイコン + 巨大な `漫画` + 罫線 + `まもなく開きます`。一瞬だけ出る।
- スリープは三日月（黒円 + 白円）と `本は、眠らない。`。時計は出さず、復帰は
  電源ボタンであることを明記。エディトリアルで静かな画面にした。

### グリッドとベースライン

- 左右 64 px、コンテンツ 944 px。基本 8 px。
- アプリの円は中心 x = 224 / 432 / 640 / 848（間隔 208、円の間隔 48）。
- タイルは x = 64 / 392 / 720、y = 928 / 1128（行間 16）。
- 文字は 8 の倍数のベースライン（時計 432、日付 512、アプリ見出し 608、
  お気に入り見出し 912、設定見出し 360 / 568 / 848、フッター 1400）。
- 文字サイズは 24 / 28 / 30 / 32 / 36 / 40 / 44 / 96 / 168 / 264。最小 24 px。
- 下半分のセクション間隔は 48 px 以上（罫線 536 → アプリ四角 584、
  アプリ名 descent 840 → お気に入り四角 888）。

## フォント

`fonts/` の 3 本は `design/mockups/fonts/` の可変フォントから fonttools で
静的インスタンス化したもの（`fvar` なし、weight 700 / 400 / 500）。ライセンスは
`OFL-NotoSerifJP.txt` / `OFL-NotoSansJP.txt`。C 側はこの 3 ファイルだけを積めばよい。

## 注意 / トレードオフ

- Noto Serif JP の数字は tabular ではない（`tnum` を持たない）。時計の桁幅は変わるが、
  部分リフレッシュ矩形を固定して毎分クリア → 再描画するのでゴーストは出ない。
  どうしても桁位置を固定したい場合は、C 側で数字ごとに固定セル（例 176 px）に
  中央置きすればよい。仕様書は固定矩形方式を採用している。
- 明るさは 16 段階で描いている。PW2 のハードウェア段数に合わせる場合は
  16 段階をそのまま 24 段階へ写像する（仕様書 §2.10 の level を 0–16 で持つ）。
- アイコン PNG は 96 px / 40 × 30 / 56 × 28 の等倍。C で拡大しない。
- `explorations/home-list.png` は比較用で、`render.sh` の生成対象外。
- 設定の更新ボタンと ± ボタンは高さ 120 / 枠 3 px / ラベル 32 px の共通ボタン。
  行の区切りは下辺のみ。
